## Configuration design

Read repository and bot login from the protected broker policy `app` block. Pin operator user, operator checkout, mirror and host guard in protected operator settings that refuse to run while unset, following `service_runtime`. Do not infer these values from the current login, hostname or checkout. `SCOPE_SHA` remains an independent operator pin: never compute a digest and trust it as approval. Derive binding counts from validated scope and request counts from actual transport/audit observations; do not label fixed expected values as measured.

Two settings options require a later design decision:

- Policy v3 `operator` block: changes `load_policy`'s exact allowed key set/version, every closed-schema fixture and the deployed Barlow policy. Requires an explicit policy rewrite and migration/negative tests.
- Separate root-owned operator env file: retains broker policy v2; use a strict allowlisted parser, protected ownership/modes/ancestors, bounded values and no shell sourcing or command substitution. Pin its path and refuse missing/unset/unknown/unsafe settings. Add refusal and policy-disagreement tests.

Unit, credential, policy/state/staging/work paths and publisher account must be operator-pinned or taken from validated broker fields; fixed host tools such as runuser need explicit platform validation. Pinning must preserve root/ownership/lock/runtime guards.
